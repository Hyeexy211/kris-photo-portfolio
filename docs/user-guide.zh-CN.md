# Kris Photography 使用说明

> 本说明描述本轮仓库源码。2026-09-23 已将旧云端内容备份到仓库外并核验，按指定 ID 清空生产库中的 3 个作品集、9 张照片，紧随删除的计数为 0/0，随后执行共享类别迁移。真实所有者完成本轮多张上传、类别与批量操作、公开展示验收；临时记录和测试网页图已清理，当时作品集／照片／类别及两个 Storage 桶对象数量均为 0。2026-09-27 公开只读复核为 0 个作品集、0 张照片、4 个后来新增的类别；它们已保留。本轮源码已发布并完成 GitHub Pages 线上复核；部分失败仅通过 mock 验证。

## 1. 这是什么网站

这是一个用 HTML、CSS 和原生 JavaScript 制作的摄影作品集。访客可以浏览作品集和照片；站点所有者可以进入有登录门槛的云端编辑界面，也可显式打开浏览器本地原型。仓库的浏览器本地默认内容已设为 **0 个作品集、0 张照片、0 个类别**；真实 Supabase 中的旧 3/9 条记录已通过限定清空另行删除。

公开站点首页、Gallery 和通用作品集页从 Supabase **只读**获取内容。云端读取失败时显示错误，不会改用当前浏览器的旧 localStorage 内容；本地模式仍只是独立原型，不会自动上传到云端。

| 目的 | 操作 | 当前结果 |
| --- | --- | --- |

| 放大照片并查看资料 | 点 Gallery 或作品集中的照片，再点灯箱内 **Photo details / 照片信息** | 灯箱可用左右按钮或键盘 ← / → 切换，按 Esc 退出；手机可在大图上左右滑动，信息区可独立滚动。只显示已填写的拍摄资料；全部为空时提示“暂无拍摄信息”。 |

## 3. 网站所有者怎样试用本地内容编辑

1. 显式打开 `admin.html?mode=local`，或在后台页面中点 **Browser-local editor**。此模式无需登录；无参数的 `admin.html` 默认是 Cloud Admin，旧地址 `admin.html?mode=cloud` 仍可使用。
2. 在 **Manage Works** 中先创建共用照片类别，再新增作品集，或点已有条目的 **Edit**。保留稳定 ID 与 slug；填写标题、短介绍、创作故事、真实封面路径、替代文字、类别和显示顺序，点 **Save Work**。本地模式的图片路径必须指向项目内已有文件。
3. 在作品集下方的选照区选择作品集，可按标题或分类查找。勾选真实缩略图后点 **Add selected / 加入所选照片** 或 **Remove selected / 移出所选照片**。加入其他作品集中的照片会先提示“移动归属”，照片仍只有一个 `collectionId`。用上移／下移按钮调整集内顺序，再点保存排序。若批量操作中途失败，状态会说明已保存数量并重新读取实际列表。
4. 在同一 **Manage Works** 区域的照片表单新增或编辑照片：填写真实图片路径、已创建的类别、可选作品集、顺序及已确认的日期、拍摄时刻、地点和器材。标签用英文逗号分隔。类别在作品集区创建、改名、合并；作品集与照片选同一份定义。批量上传文件只在 Cloud Admin 中可用，本地模式不会上传图片。
5. 本地模式可以选一张文件仅用于 **JPEG EXIF 候选值审核**，该文件不会上传或变成项目图片。逐字段查看、修改、接受或拒绝；“接受”只把候选值复制到照片表单，仍须点保存。手工已填字段不会因重新选图自动覆盖。无 EXIF、损坏 EXIF 或不支持的格式会提示“未读取，可手填”；地点仍须手工确认，GPS 坐标不会进入表单或公开资料。
6. 删除作品集前会显示关联照片数及结果；确认后照片解除关联，仍留在 Gallery。单独删除照片仍是另一项明确操作。页面底部的 **Reset Content** 经确认后清空当前浏览器的作品集、照片和类别；它不会恢复旧种子，也不会清空 Supabase。

本地模式只把记录保存在当前浏览器的 `localStorage`。它不会修改 `data/` 文件、图片文件、Supabase、Git 仓库或其他设备。图片字段在本地模式填写的是**已有图片的相对路径**；表单不会把选中的图片文件上传进项目。路径必须真实存在且大小写一致，否则浏览器会显示坏图。

**当前容易误解的一点：**公开页面配置为 Supabase 时，`admin.html?mode=local` 的本地修改不会出现在公开首页和作品集页，云端故障也不会触发本地回退。只有明确把开发环境的数据源设为 `local` 时，公开页面才读取该浏览器的本地记录。`file://`、`http://127.0.0.1:4173` 与 GitHub Pages 是不同来源，本地存储不会互通。

## 4. 本地预览与项目文件

在项目根目录运行：

```sh
python3 -m http.server 4173 --bind 127.0.0.1
```

然后在浏览器打开 `http://127.0.0.1:4173/` 看当前源码，或打开 `http://127.0.0.1:4173/admin.html` 看默认 Cloud Admin；试用本地原型请打开 `http://127.0.0.1:4173/admin.html?mode=local`。运行服务器的终端中按 `Ctrl+C` 停止。直接双击 `admin.html` 得到的 `file://` 地址不是线上网站；页面会提示改用线上或 HTTP 预览地址，不能用它判断云端发布结果。已有的 `file://` 本地记录仍属于原浏览器来源，不会自动转到 HTTP 或 Supabase。

| 位置 | 用途 |
| --- | --- |
| `index.html`、`collection.html`、`photo.html` | 首页、通用作品集页、通用照片页。旧的 `photos/`、`projects/` HTML 入口已退役，图片文件保留。 |
| `data/collections.js`、`data/photos.js` | 空的浏览器本地默认内容；不要填写未经确认的拍摄资料。 |
| `js/content-service.js`、`js/repositories/` | 公开页面的数据读取和本地数据保存。 |
| `admin.html`、`js/admin.js` | 默认 Cloud Admin；`?mode=local` 保留本地编辑原型。 |
| `images/`、`css/` | 真实照片、响应式网页图和页面样式。 |
| `dist/` | Sites 预览和托管所用的静态副本，已被 Git 忽略；它不等于根目录源码。 |

如果要预览 `dist/`，可改用 `python3 -m http.server 4173 --bind 127.0.0.1 --directory dist`。修改根目录源码后，要先同步对应文件到 `dist/`，否则看到的可能是旧内容。不要只修改 `dist/`。

## 5. 云端数据与 Cloud Admin 的现状

- **当前源码的数据边界：**公开页面通过 Content Service 一起读取 Collections 和 Photos；任一云端读取失败便显示读取错误，不展示旧浏览器缓存。本地编辑不会写入 Supabase。生产库旧记录的备份、限定清空和 3/9→0/0 结果见 [`content-reset-audit-2026-09-23.md`](content-reset-audit-2026-09-23.md)；验收清理当时的作品集／照片／类别及两个 Storage 桶对象数为 0。2026-09-27 公开数据复核为 0/0/4；保留后来新增的类别。
- **数据库配置：**2026-09-23 曾验证所有者身份、`story`、`collection_order`、`capture_time` 和作品集删除时 `ON DELETE SET NULL`。当时也确认 `portfolio-web` 公共网页图桶、`portfolio-originals` 私有原图桶及四条所有者 Storage 策略存在。本轮共享类别迁移已在生产库执行；新环境仍应核查真实 schema 后按迁移说明操作。
- **较早一轮真实云端复测：**当时使用 1 个临时作品集和 2 张临时照片验证单张上传／替换、故事、拍摄时刻、归属、集内排序、分类修改和删除；随后清理了 15 个测试网页图并核对旧记录。这些记录不证明本轮多文件队列、批量删除、类别表和零内容状态已通过真实云端验收。
- **本轮真实云端复测：**所有者在作品集区一次选多张照片，逐张保存资料；创建、重命名和合并共用类别；批量修改类别和归属、跨作品集移动、保存集内顺序与删除记录，并在公开作品集和 Gallery 核对展示。验收后删除 2 个临时作品集、2 张照片、1 个类别、12 个测试 WebP，以及 4 个自动生成的零字节 `.emptyFolderPlaceholder`。2026-09-23 清理结束时只读 SQL 显示 `collections/photos/categories=0/0/0`，`portfolio-web/portfolio-originals` 对象数为 `0/0`；2026-09-27 公开数据复核为 `0/0/4`，新增类别予以保留。部分失败仅通过 mock 模拟验证，尚未完成真实故障注入验收。
- **权限验证范围：**匿名数据库新增返回 `42501`，匿名 Storage 上传返回 `403`。第二个已登录非管理员账号、重复键覆盖和其他 Storage 拒绝场景尚未完成实测。详细结果与边界记录在 [`crud-test-report-2026-09-23.md`](crud-test-report-2026-09-23.md)。
- **图片上传的设计边界：**Cloud Admin 接受最长边至少 1800px、文件不超过 25 MiB、总像素不超过 4000 万的 JPEG、PNG、WebP 或可解码 AVIF，横图和竖图均可。选择后可看预览；不选新文件就保留原图。选择文件时先在浏览器本地尝试读取 JPEG 的常见 EXIF 候选值，只有逐字段接受并保存后才公开。保存时浏览器经 Canvas 保持比例，按最长边生成 640、1200、1800px 三份 WebP，`srcset` 使用各导出图的实际宽度；检查无 EXIF/XMP 后上传，再把 URL 写入 Supabase。原始文件不会上传，替换后的旧网页图暂不自动删除。浏览器本地原型仍使用已有图片的相对路径字段。详情见 [`supabase-admin-setup.md`](supabase-admin-setup.md) 与 [`supabase-storage-setup.md`](supabase-storage-setup.md)。

Cloud Admin 的使用步骤如下。共享类别迁移已在本项目生产库执行；本轮临时验收记录已清理。以后测试仍应使用可删除的临时记录：

1. 在站点根地址后加 `admin/` 打开 Dashboard，登录所有者账号，进入 **Manage Work**；也可直接打开默认云端模式的 `admin.html`。旧地址 `admin.html?mode=cloud` 仍兼容。后台的 Gallery 链接只通向公开画廊，不提供第二套照片编辑表单。
2. 在作品集区先创建照片类别，再创建 Collection：填写标题、介绍、故事、类别等，点 **Choose image** 选封面，确认预览后保存。编辑时选新文件可替换封面；不选则保留当前封面。
3. 选定作品集后，可从本机一次选择多张照片。逐张检查预览和资料，未知字段留空；JPEG EXIF 候选值须逐字段接受才会进入表单。保存时查看各张结果，部分失败只重试失败项，不要重复提交已成功项。
4. 已保存照片仍在作品集区编辑。勾选多张照片后可明确设置共同类别、加入或移出作品集、移动到另一作品集、调整集内顺序或删除记录；未选择的字段不会以空值覆盖各张已填资料。删除前检查数量和提示，记录删除不会自动删除保留的旧网页图对象。

Cloud Admin 写入 Supabase 后，通用作品集和照片页面会读取新记录，但 GitHub Pages 的静态 HTML 不会自动改变。旧照片的独立静态分享页已经退役；通用照片页目前只有通用初始社交资料。公开仓库中仍保留原片和旧网页图，因此页面不展示旧图**不等于**旧图片地址无法直接访问。
